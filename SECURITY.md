# Security Policy

## 🛡️ Supported Versions

**Snoozer.uk** is currently in active **Pre-v1.0** development. Security patches and vulnerability fixes are actively applied to the following branches and releases:

| Version / Branch | Supported          | Status |
| ---------------- | ------------------ | ------ |
| `main`           | :white_check_mark: | Active Pre-v1.0 development branch (receives all security updates) |
| Feature / PR branches | :x:           | Unreleased work-in-progress; not supported for production |

---

## 🏗️ Security Architecture & Scope

Snoozer.uk is built around a strict separation between **authenticated creator mutations** (Studio) and **unauthenticated public reads** (Visitor profiles), backed by **Supabase PostgreSQL Row-Level Security (RLS)**, **Supabase Auth**, and **Supabase Storage**.

### In-Scope Areas
* **Authentication & Session Handling:** GoTrue / Supabase Auth flows, session cookies, and creator access controls.
* **Database & Storage Isolation:** PostgreSQL Row-Level Security (RLS) policies, atomic Studio draft/publish workflows, and Object Storage bucket permissions.
* **Application Layer:** Next.js App Router server actions, API routes, XSS/CSRF protections, and input sanitization on public profile rendering.
* **Infrastructure & Supply Chain:** Docker configurations, Render deployment blueprints (`render.yaml`), and direct npm dependencies.

> [!NOTE]
> For deeper context on system boundaries and design decisions, please review our threat model and Architecture Decision Records in [`docs/`](./docs).

### Out-of-Scope & Self-Hosted Instances
* **Third-Party Self-Hosted Deployments:** Because Snoozer.uk is self-hostable, vulnerabilities caused by misconfigured third-party hosting environments, exposed `.env.local` files, or altered RLS policies on external instances are outside the scope of this repository.
* **Local Development Defaults:** Default keys or Inbucket test endpoints generated by `supabase start` for local testing are intentionally non-secret.

## 🚨 Reporting a Vulnerability

We take the security of **Snoozer.uk** and its self-hosting community seriously. If you discover a security vulnerability, please disclose it responsibly so we can resolve it before public exposure.

> [!CAUTION]
> **Do not** open a public GitHub Issue, Pull Request, or Discussion to report a security vulnerability.

### How to Submit a Report

1. **GitHub Private Vulnerability Reporting (Preferred):** Navigate to the **[Security Advisories tab](https://github.com)** of this repository and click **"Report a vulnerability"** to open a confidential report.
2. **Direct Private Contact:** If GitHub private vulnerability reporting is unavailable, contact the repository maintainer ([@Truwty](https://github.com/Truwty)) directly through an established private contact channel.

### What to Include in Your Report

To help us reproduce and patch the issue rapidly, please provide:

* **Vulnerability Category:** (e.g., RLS bypass, privilege escalation, stored XSS on public profiles, SSRF, auth flaw)
* **Affected Versions / Commit:** The specific commit SHA, release tag, or branch (`main`) tested.
* **Step-by-Step Reproduction:** Clear instructions, HTTP requests, or a minimal proof-of-concept (PoC)—ideally reproducible against the local Docker/Supabase stack (`npx supabase start`).
* **Potential Impact:** What an unauthenticated visitor or malicious creator could access or modify.

> [!WARNING]
> **Keep Sensitive Data Out of Reports:** Never include real user credentials, Supabase `service_role` keys, payment information, or personally identifiable information (PII) in your reports or public issues. Always use dummy accounts and redacted tokens.

---

## ⏱️ Disclosure & Response Timeline

* **Acknowledgment:** We aim to acknowledge receipt of your vulnerability report within **48–72 hours**.
* **Investigation & Fix:** We will validate the reproduction steps, assess severity, and develop a fix (including regression tests in Vitest or Playwright where applicable).
* **Release & Credit:** Once the patch is merged into `main`, we will publish a GitHub Security Advisory and credit you for the discovery unless you request anonymity.

---

## 🤝 Safe Harbor

We welcome good-faith security research. Testing conducted against your own local instance (`supabase start`) or in compliance with this policy—without disrupting live services, accessing other users' data, or exfiltrating sensitive information—is considered authorized. Thank you for helping keep **Snoozer.uk** safe!
