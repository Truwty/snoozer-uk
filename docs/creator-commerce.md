## Proposed Connect model — sandbox implementation decision, live release unapproved

Accounts API: Accounts v2, explicit `dashboard: full`, `defaults.responsibilities.fees_collector: stripe`, `losses_collector: stripe`, merchant configuration and requested card_payments. No legacy account type, platform transfers, recipient-only accounts or public-preview Express configuration. Independent creators sell their own digital products and own the customer relationship; direct charges keep the payment in the creator's connected account. This is a software-platform model, separate from existing Snoozer premium subscriptions and Ko-fi support links.

Creator onboarding: authenticated verified owner explicitly starts onboarding; the server creates exactly one sandbox account per owner with an idempotent operation binding. Stripe-hosted onboarding collects sensitive identity and business details directly. Return navigation is not proof of completion. Retrieve current capability status (`configuration.merchant.capabilities.card_payments.status`) and permitted responsibilities before every new Checkout, and recheck ongoing requirements. Full Dashboard access uses Stripe's normal account login. No identity data, country eligibility or agreement acceptance is fabricated by Snoozer or the agent.

Hosted onboarding avoids a new embedded dependency. Embedded account_onboarding, notification_banner, account_management, payments and payouts components remain an optional future in-app enhancement; the notification banner is required if that embedded route is introduced. Current full Dashboard/hosted requirement-remediation links must serve that operational need before release. The planner's embedded/custom-only tree omitted the officially supported hosted option; it has not been accepted with a false embedded selection.

Negative balance liability: the proposed full/stripe/stripe direct-charge combination assigns connected-account negative balances to Stripe. This does not remove Snoozer's platform policy duties or guarantee legal eligibility.

Risk management: creators handle refunds/disputes in their full Dashboard; Snoozer must verify connected-account events and suspend digital delivery on refunds, disputes or fraud signals. Seller/content moderation, safe file handling, support, restricted-product enforcement and abuse controls remain release requirements. Radar for Platforms is a possible additional control, not provisioned or promised free.

Funds: buyer → creator connected-account charge → Stripe processing fees → creator balance. No platform transfer, held customer balance or payout scheduling. Sandbox platform transaction fee is zero (`application_fee_amount` omitted), pending an explicit commercial pricing decision. No estimated Stripe fee gross-up. Existing SaaS subscription fees continue through the existing platform billing implementation; do not migrate those customers or invent customer_account mappings. Actual costs depend on region/method: [Stripe pricing](https://stripe.com/pricing).

Webhook integration: verify the signature of the dedicated sandbox connected-account event destination, reject livemode/mismatched account data, and persist idempotent receipts before reconciliation of current provider state.

## Private version snapshots (migration70 hosted)

Only the service can freeze the snapshot; SQL rechecks verified ownership, saved revision, ready file, profile media scope and stored size/MIME under the existing account/media locks. Copy, price, currency, file identity, bytes and fingerprint cannot be edited. Retry of the same tuple/hash returns the existing UUID; a changed hash fails closed. Five snapshots per product, at most100 per account, no second physical file or storage allowance.

Discarding all private versions releases that guard; it does not remove the draft or PDF. Profile deletion still cascades unsold snapshots and uses the existing delayed media cleanup. The file FK is deferred so the complete unsold profile cascade can finish atomically. No public API, buyer permission, malware scan, order or purchase-retention claim is introduced.
