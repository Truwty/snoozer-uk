# Referral attribution

Free on all plans. A verified account with a published profile can enable one stable referral signup URL in Studio → Growth. Disabling it stops new acceptance; unpublished/deleted source profiles cannot receive new credit. Only signup with an explicitly unchecked opt-in and email verification within 24 hours is eligible. Invalid/old/disabled/self claims grant no credit. Account ownership is derived from verified Auth identity, not form IDs.

No clicks, cookies, rewards, payments or entitlements are attributed. User-editable Auth metadata contains only a claim, never authority for money or access. Each account can be attributed once. Email verification does not prove a unique person or legitimate acquisition; figures are labelled accordingly. No paid conversion or causal claim is made.

Creators see verified-account counts and current claimed/live profile stages for a rolling 90-day acceptance window. Profile stages require five verified accounts. Reports expose no names, IDs, emails or individual history. Attribution connections are retained until withdrawal or account deletion; the reporting window is not a raw-data deletion claim. Withdrawal removes the referrer link and signup metadata, retaining a minimal account-scoped exclusion marker to prevent re-attribution until account deletion. Referrer deletion nulls connections; member deletion removes rows.

All tables are private/RLS enabled with no direct API roles. Four verified-owner RPCs enable/disable, accept the current account’s signup claim, withdraw and read aggregates. Identity-row locks serialize acceptance/withdrawal; the code row is locked while accepting so disable cannot race past it. Optional attribution failures after email confirmation lead to Growth with an honest warning and retry, preserving the verified session. No Auth database trigger can break registration. SQL and validation tests cover positive, privacy, permission, expiry, invalid/disabled/self and withdrawal/deletion boundaries; disposable provider signup browser verification is pending.

Operational diagnostic: Growth reports availability errors without leaking database details. An unconfirmed signup can retry within the 24-hour eligibility window. Never backfill attribution for existing accounts or override withdrawal. No new service, dependency or credential is needed. Abuse protection is limited to verified account identity, single attribution, opt-in/age checks, no financial incentives and honest cohort reporting; bot farms remain a moderation concern.
